# 36 · 逐按钮结果审计（T49）

> 起因：用户要求「检查所有按钮是否真的按预期工作，而不是 happy buttons」。
> 旧审计（2026-10-16，27 项）有 5 项只断言按钮存在，且不覆盖设置窗/搜索窗。

## 方法

- `scripts/button-audit.mjs` 启动真实应用（隔离 `MYAGENT_HOME`、mock LLM、mock MCP 服务器），经 CDP
  驱动**主窗 / 设置窗 / 搜索窗的全部可点击控件**，每项断言控件存在的**目的**：
  daemon 状态（`sessions.get`/`skills.list`/`settings.*`）、窗口状态（`win-state`）、磁盘文件、
  **LLM 实际收到的请求内容**、跨窗口同步。存在性断言不计为通过。
- 测试接缝 `MYAGENT_TEST_SEAMS=1`（仅审计用，主进程内）：OS 文件对话框从队列应答、外链记录不外开、
  `test-seam` 可触发原生菜单项 click、恢复主窗。`win-state` 是只读窗口动作（非接缝）。
- Linux 无 DISPLAY 时 Xvfb + openbox（最大化/最小化需要窗口管理器才有意义）；随机 CDP 端口 +
  校验 vault 目录属于本次 `MYAGENT_HOME`，防止连到残留实例；退出时杀整棵进程树。
- `npm run verify` 第 3b 步运行，结果进验收报告 T49；任一项 FAIL 即非 ALL GREEN。

## 平台语义（按平台断言，不是跳过）

- 关闭 ×：Windows 隐藏到托盘、可恢复；其他平台关闭主窗，最后一个窗口关闭后应用退出（F16 既有设计）。
- 「关于」分区只有信息项（禁用态）——按设计是展示，不计为「无效按钮」。
