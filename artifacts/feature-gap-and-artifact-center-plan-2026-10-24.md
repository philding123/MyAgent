# MyAgent 与 WorkBuddy 功能差异报告及产物中心实施方案

- 报告日期：2026-10-24
- 状态：调查结论已归档；实施方案待执行，本报告不代表功能已实现。
- 调查范围：当前仓库源码、已有 WorkBuddy 观察记录、设计文档、历史验收报告，以及用户本次反馈。
- 核心诉求：像 WorkBuddy 一样，在会话右侧通过可折叠面板查看产物，并能打开产物所在路径。
- 本次交付：仅新增报告，不修改业务代码，不重新生成历史验收报告。

## 1. 结论摘要

当前本工具并非完全没有产物预览，而是采用“聊天消息内产物卡片＋独立预览窗口”，未实现用户期望的“右侧可折叠产物列表与预览”。打开所在文件夹、默认应用打开、复制路径也缺少专门入口。

此外，产物链路有两项可靠性缺口：

1. 实时事件携带产物元数据，但工具消息落库没有完整保存该字段，历史会话回放也没有重建产物卡片。文件可能仍在磁盘，查看入口却丢失。
2. `write_file` 在调用开始时就创建卡片，尚未确认写入成功；失败或拒绝后未撤销卡片。通过命令生成、但没有调用 `present_file` 的文件也不会自动成为正式交付产物。

因此，建议优先建设“会话产物中心”，按“可靠记录 → 右侧面板 → 路径操作 → 预览完善 → 实机验收”推进，而非只增加一个预览按钮。

### 3.1 已有能力，不应重复开发

- `present_file` 对源文件执行沙箱读取检查，将文件复制到用户可见交付目录。
- 默认交付位置为 `~/MyAgent/<时间戳>/`；`MYAGENT_DELIVERY_DIR` 可覆盖交付根目录，但不是用户界面设置。
- 成功交付的工具结果携带 `artifact:{path,name}`，renderer 会创建卡片并尝试自动打开独立预览窗口。
- 点击实时卡片可打开预览；任务顶栏也可以选择本地文件预览。
- 预览内容通过 daemon 的 `files.readBinary` 获取，并经过读取权限与大小检查。
- docx、pdf、pptx、表格、图片及文本已有渲染基础，可复用。

### 3.2 三种“路径”操作必须区分

1. **选择文件来预览**：打开文件选择器，选中一个已有文件。目前已有但入口不明显。
2. **打开产物所在路径**：在资源管理器等系统文件管理器中定位已交付文件。当前缺失，是本轮核心范围。
3. **选择产物保存路径**：更改交付位置或另存副本。当前缺失，先作为可选后续项，不与“选择工作空间”混为一谈。

### 3.3 当前预览限制

- 文件读取上限为 25MB。
- PDF 最多渲染 50 页；表格最多展示 12 个工作表。
- 文本预览最多展示 200000 个字符。
- HTML／Markdown 当前作为文本显示。
- 不支持的类型提示不支持，没有系统应用兜底。

以上限制本身不一定要全部取消，但必须在 UI 明示，不能将部分展示描述为全文预览成功。

## 4. 当前实现链路与根因

### 4.1 实时链路

`present_file` 成功复制 → 引擎附加 artifact 字段 → EngineHost／daemon／main 转发事件 → renderer 创建卡片 → `rpc.window` 的 `openPreview` → 独立 BrowserWindow → `files.readBinary` → 按类型渲染。

实时预览不是整个链路都未接通；主要差异在预览宿主形式、产物索引和文件操作。

### 4.2 历史链路缺口

daemon 保存 `tool_result` 时，`tool_json` 只写入 `ok` 和 `detail` 等已有字段，没有完整保存 artifact。renderer 的 `openSession` 回放普通工具消息，没有从持久记录重建产物列表。

这也是为什么已有 F51/T43 普通消息落库验收通过，仍不能证明产物历史恢复完整。

### 4.3 宿主选择属于既有设计偏离

[文档预览设计](../design/20-mermaid-preview.md) 第 33–46 行明确选择独立预览窗，以保持聊天轻量。右侧预览不是一个已存在但未开启的开关，而是需要修订设计的交互能力。

## 6. 实施目标与范围

### 6.1 首轮必须交付

1. 当前会话右侧有统一产物列表与预览区域，可展开和折叠。
2. 产物成功交付后自动登记；切换会话和重启后可恢复。
3. 点击聊天卡片或右侧列表均选中同一产物；默认在右侧预览，保留独立窗口选项。
4. 提供“打开所在文件夹”“默认应用打开”“复制完整路径”。
5. 缺失、拒绝访问、超限、不支持类型、渲染失败均有明确状态。
6. 后台会话完成交付后，不抢占当前会话；切回时能发现其产物。

### 6.2 首轮不包含

- 全盘扫描、任意命令输出文件自动收集、文件版本控制、在线协同编辑。
- 无条件执行生成的 HTML／脚本、打开可执行文件或绕过沙箱。
- 变更默认交付目录、可选另存副本：作为 P2 后续项，不阻塞右侧预览与目录定位。
- 同时改造 IM、分享、联网检索或专家体系。

## 7. 分阶段实施方案

### 阶段 0：固化基线与设计契约

**WorkBuddy 观察**：用户反馈存在右侧折叠预览和路径查看；已有记录确认其交付目录与预览组件族，但没有证明完整右侧交互细节。

**复现设计**：实施前登记本机 WorkBuddy 版本、对应操作截图或录屏，明确右侧列表、折叠、打开路径的实际行为。若无法运行，则标记“参考用户反馈的目标设计”，不声称像素等价。修订 F20/F44/F47/F51 相关设计，必要时分配新的全局功能与测试编号。

**验证方法**：形成观察、推断、目标设计分栏的基线；检查无旧 F/T 编号冲突。记录当前 MyAgent 启动方式和构建来源，避免混淆源码与安装包。

### 阶段 1：可靠产物记录与历史恢复（P0）

**复现设计**：优先复用现有消息 `tool_json` 的版本化可选字段保存产物元数据，不为首轮贸然新增独立存储表。建议字段包括 schemaVersion、sessionId、toolCallId、path、name、sourceTool、createdAt、交付状态；稳定身份与路径去重规则在设计中明确。

- daemon 是持久记录的权威来源，不能只依赖当前 renderer 是否收到事件。
- 对读取出来的历史 JSON 做容错解析，兼容无 artifact 的旧记录。
- 以成功结果为准登记产物；不能从工具摘要文本反解析路径。
- `write_file` 工作文件与 `present_file` 正式交付区分；如保留工作文件入口，必须在写入成功后出现。
- 后台会话产物正常落库；删除会话按既有数据语义处理，不顺带删除磁盘交付文件。
- 旧记录若未保存结构化路径，不假称可完整恢复；首轮不批量猜测、扫描补档。
- 对云沙箱产物显式标明远端／本地可用性；不能将远端路径交给本机文件管理器。

**预计影响**：engine 结果字段（如需补充）、daemon 事件记录、renderer 会话回放及共享的产物归一化逻辑；核验 sqlite/json 双后端兼容性。

**验证方法**：成功／拒绝／失败、重复事件、多文件、同名不同路径、旧消息、非法 JSON、会话切换、后台交付、应用重启后的列表恢复。不得出现失败工具对应的可用产物卡片。

### 阶段 2：右侧可折叠产物中心（P1）

**复现设计**：在主窗增加右侧宿主，包含产物列表、当前文件信息、操作栏和预览区域。聊天卡片与右侧列表共享选中状态。默认以内嵌预览替代交付后自动弹独立窗口，独立窗口保留为显式操作。

- 折叠不删除产物记录，重开面板恢复当前选中项。
- 面板状态按会话隔离；后台交付不得切换当前会话或抢焦点。
- 明确空态、加载态、错误态、缺失文件态，支持连续切换文件而不显示过期异步结果。
- 适配窗口缩放、明暗主题、长文件名和键盘操作；窄窗口不得挤坏聊天输入区。
- 提取可复用的预览渲染模块，独立窗与内嵌宿主共享读取、分发和资源清理逻辑；不引入 Node 权限或新的 preload 暴露面。

**预计影响**：`app/renderer/index.html`、`style.css`、`src/app.js`、`src/preview.js` 及必要的新预览模块；构建脚本按实际入口变化调整。

**验证方法**：产物到达展开、点击选择、折叠再展开、多文件切换、跨会话状态隔离、窄窗、主题、独立窗入口。截图与操作结果共同验收，不能仅检查 DOM 存在。

### 阶段 3：路径与系统应用操作（P1）

**复现设计**：工具栏／菜单提供“打开所在文件夹”“默认应用打开”“复制完整路径”“独立窗口预览”。操作目标来自已验证的产物记录，不接受 renderer 任意传入未经检查的系统目标。

- 不新增 IPC handle。业务校验通过 daemon methods，原生文件管理器／默认应用动作通过现有 `rpc.window` 窄通道完成。
- 使用原生 API，不拼接 shell 命令，不将本地文件路径塞进只接受 HTTPS 的 openExternal。
- 校验记录归属、路径规范化、文件类型、存在性和沙箱权限；考虑符号链接、目录替换和校验到使用间的竞态。
- 默认应用打开可能触发活动内容，不视为纯读取；对可执行文件、脚本、快捷方式、危险 URI 与不受信任网络路径采用明确拒绝或确认策略。
- 不得由模型事件自动触发系统应用打开；只响应用户明确点击，必要的确认不能记忆批准。
- 文件已丢失时明确提示；不要静默跳转到无关目录。父目录可访问时是否提供单独定位动作需明确文案与策略。
- 审计模式记录目标与结果，不真实启动外部程序；实际 Windows 文件定位仍需手工验证。

**预计影响**：daemon 方法表及权限校验、main 窗口动作、renderer 菜单和既有测试接缝；不新增宽泛系统执行接口。

**验证方法**：中文／空格路径、缺失文件、越权路径、伪造记录、符号链接、危险扩展名、确认拒绝、原生 API 失败及复制结果。T08/T09/T10 与窄 IPC 不变式必须回归。

### 阶段 4：成品预览与限制提示（P1）

**复现设计**：Markdown 使用已有安全渲染基础；HTML 如支持成品模式，必须置于隔离、禁脚本、无 Node／preload 桥的宿主中，并限制网络、导航、弹窗、下载和活动内容。原文查看作为可切换模式保留。

- 生成的 HTML 内容始终是不可信数据，不因来自 agent 而获得系统能力。
- 不允许静默外发文件内容或让预览自动访问外网，符合无遥测和本地预览边界。
- 对大小、页数、sheet 数、字符数截断明确提示；保留安全的系统打开入口。
- 统一独立窗与右侧预览的错误语义；不支持的类型不能伪装成预览成功。
- 切换文件时清理 Object URL、PDF 任务和预览实例，避免内存泄漏与旧内容闪回。

**验证方法**：真实 HTML／Markdown／图片／PDF／docx／xlsx／pptx fixtures；XSS、远程资源、导航、弹窗和下载被阻止；超限与损坏文件有提示；无意外网络请求。

### 阶段 5：构建、回归与 Windows 实机验收

**复现设计**：补充单元、集成和 UI 效果断言；先构建再测试，保证实际加载的 dist 对应当前源码。通过 mock LLM 生成脚本化交付，不消耗真实 API。

**验证方法**：运行 `npm run build` 和 `npm run verify`，以新生成的 `artifacts/acceptance-report.md` 为准；有 FAIL 必须归因并修复。随后在 Windows 可见窗口及本轮目标安装包验证完整交付链路，记录构建来源、测试时间、截图与实际路径操作结果。未经实机验证的系统行为保留“未验证”，不能被测试接缝代替。

## 9. 风险与控制

- **历史数据不可追溯**：过去丢失的产物字段无法凭空恢复。保留旧消息，明确新能力的兼容边界，不猜测路径。
- **权限绕过**：预览、系统打开与目录定位的安全语义不同，不能统一当作无害读取。
- **HTML 活动内容**：成品预览可能引入脚本、网络与导航风险，必须隔离并提供安全测试。
- **构建版本混淆**：源码变化不代表当前 dist 或已安装应用更新，必须记录实际运行来源。
- **预览性能**：避免同时加载全部大文件；按需渲染，明确上限并正确清理资源。
- **范围膨胀**：首轮不同时承担文件历史、自动全盘收集、保存目录设置或其他平台能力改造。
